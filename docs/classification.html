Stage 06 · Classification

Can we predict a cancellation at booking time?

Five classifiers were trained on the same stratified 80/20 split (69,296 training / 17,324 test bookings) using 25 attributes known when the booking is made. Each model was tuned with cross-validation on the training set only.

Setup

X

25 attributes → 53 columns

18 numeric + 7 categorical (one-hot). Attributes recorded after the outcome are excluded: reservation_status, assigned_room_type, room_changed, parking spaces, country, realized_revenue.

y

is_canceled

Positive class: Canceled (27.7%). Majority voting alone gives 72.3% accuracy — every model must beat this.

CV

Holdout + cross-validation

Stratified 80/20 holdout. Hyperparameters chosen with stratified 10-fold (tree) or 5-fold GridSearchCV; the test set is used once.

Decision tree: choosing the depth

The root split, calculated by hand with information gain, is lead_time ≤ 8.5 (H(D) = 0.851 bits, Gain = 0.041) — the same split scikit-learn chooses. The depth was then selected with stratified 10-fold cross-validation.

Validation error is lowest at max_depth = 9. Deeper trees keep lowering the training error but the validation error rises — overfitting.

FindingThe random forest is the best model (80.7% accuracy, F1 59.6%, AUC 0.837). The decision tree is close (79.2%) and easy to explain. Naive Bayes finds the most cancellations but raises the most false alarms — the trade-off between precision and recall.

Lead time, price, arrival date and special requests carry most of the signal.
