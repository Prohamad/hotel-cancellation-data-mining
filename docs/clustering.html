Stage 07 · Clustering

Four kinds of bookings, found without the label

K-Means groups bookings by five normalised attributes — lead time, nights, price, guests and special requests. The class label is not used to build the clusters; it is only used afterwards to describe them. Hopkins, K-Medoids, AGNES (four links) and DBSCAN were then compared against it.

Is the data clusterable?

The Hopkins statistic compares distances to nearest neighbours for random points and for real bookings. A value near 0.5 means random data; a value near 1 means a clear cluster structure. With 200 sampled points the result is H = 0.987, so clustering is meaningful here.

Choosing k

The empirical rule k ≈ √(n/2) gives 208 — far too many to describe the data. The elbow of the SSE curve is at k = 4.

K-Medoids (PAM)

Same idea as K-Means, but each cluster centre is a real booking (a medoid), which makes it less sensitive to extreme values. It needs a full distance matrix, so a 2,000-booking sample was used. Cluster sizes are 737 · 592 · 335 · 336, silhouette 0.301, total loss 363.4.

DBSCAN (density-based)

DBSCAN needs no k. A point is a core point if at least MinPts bookings lie within distance Eps; points reachable from no core point are noise. It ran on a random sample of 20,000 bookings because the neighbour search needs a lot of memory.

Chosen: Eps = 0.1, MinPts = 20 → 15 clusters, 379 noise points (1.9%), silhouette 0.356. Noise bookings have longer lead time (154 vs 79 days), longer stays (7.6 vs 3.6 nights) and higher adr (€157 vs €106), but the same cancellation rate (0.27), so unusual bookings do not cancel more often.
